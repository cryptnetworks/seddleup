# Screenshots

These screenshots use bundled demo data from the static SeddleUp application demo. They are intended to show the core application flow without exposing private deployment data. The application supports the same calm forest, sage, clay, and warm-neutral design system in both light and dark modes.

## Dashboard

The dashboard gives each user a quick read on active trips, total participants, balance-visible expenses, items needing review, and the next settlement suggestions.

![SeddleUp dashboard showing trip summaries, status mix, and settlement queue](https://raw.githubusercontent.com/cryptnetworks/seddleup/main/docs/assets/screenshots/seddleup-dashboard.png)

## Trip Ledger

Trip detail pages combine participants, expense history, balances, settlements, and recent activity so a group can understand the whole ledger in one place.

![SeddleUp trip ledger showing participants, balances, expenses, and settlements](https://raw.githubusercontent.com/cryptnetworks/seddleup/main/docs/assets/screenshots/seddleup-trip-detail.png)

## Expense Entry

Expense entry supports payer selection, category, status, notes, and explicit participant shares so costs are split only across the right people.

![SeddleUp expense entry form with payer, status, shared participants, and notes](https://raw.githubusercontent.com/cryptnetworks/seddleup/main/docs/assets/screenshots/seddleup-expense-entry.png)

## Account And Payment Handles

Account pages keep user-facing settings and settlement handles close to the workflow, while sensitive runtime configuration remains in environment variables or the admin pages.

![SeddleUp account page showing local profile state and payment handles](https://raw.githubusercontent.com/cryptnetworks/seddleup/main/docs/assets/screenshots/seddleup-account-local-state.png)
